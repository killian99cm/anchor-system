# 每日 14:30 盘中建议推送（daily_advice）说明

> 生效：2026-08-09 ｜ 状态：已上线，端到端实测通过
> 用户需求：「每天下午两点半，根据实时行情和 Anchor 给我买卖建议」「每天都推」「数据必须是最新的、准确的，不是瞎编的」

---

## 一、功能概述

每个交易日 14:30，自动完成：拉实时行情 → 按 Anchor 规则检查信号 → AI 结合知识库写建议 → 推送到用户微信。

用户无法用电脑时，这是查看 Anchor 数据 + 获取盘中建议的移动端入口。

---

## 二、完整链路（排查问题时按此顺序溯源）

```
Windows 计划任务「Anchor每日建议」
（周一至五 14:30，schtasks）
        │
        ▼
daily_advice.py（05-scripts/）
        │
        ├─ ① 读 portfolio_data.json（桌面，用户确认数据）
        │      └→ data_processor.py 规则引擎（与看板同一套逻辑）
        │             └→ 状态：操作次数 / 回撤 / 冻结 / 持仓分层
        │
        ├─ ② 妙想 API 拉实时行情（东方财富，MX_APIKEY 环境变量）
        │      ├─ index:   上证指数、科创50 收盘+涨跌幅
        │      ├─ sector:  半导体、创新药、证券 板块涨跌幅
        │      ├─ premium: 纳指ETF 折溢价率
        │      └─ etf:     515180、国泰黄金ETF 最新价
        │      （每天共 4 次调用，失败则当天跳过，绝不发假数据）
        │
        ├─ ③ 规则信号生成（build_signals，全部基于真实数据）
        │      ├─ 月操作次数（ops_state：count/max/是否超限）
        │      ├─ 创新药 8/20 时间止损（pending_actions）
        │      ├─ 纳指溢价率 >3% 冻结 / ≤3% 可建仓（实时值）
        │      ├─ 回撤状态（drawdown_state）
        │      ├─ 板块异动 ≥2%（止盈/回踩提示）
        │      └─ 🆕 止损确认自动化（v3.5.2）：pending_actions 含「止损确认」时，
        │             实时板块涨跌 vs 文案阈值（默认 0.5%）→ 输出【执行止损一半】或【延期一天】
        │             （案例：8/10 半导体 -8.53% 触发 → 次日 14:30 板块翻红 → 自动判定延期）
        │
        ├─ ④ 组装「事实简报」（数字全部由代码生成，AI 不得改动）
        │
        └─ ⑤ AstrBot cron API 创建一次性任务（run_once）
               POST http://127.0.0.1:6185/api/v1/cron/jobs
               body: { note=简报+防幻觉prompt, session=微信会话,
                       run_once=true, run_at=now, origin="api" }
                      │
                      ▼
               AstrBot Agent（deepseek）
                      ├─ 读简报（真实数据）
                      ├─ 检索知识库 anchor（规则/持仓/待办）
                      └─ 调 send_message_to_user 推送到微信
                      └→ 任务执行完自动删除
```

**推送目标**：`REDACTED_WECHAT_SESSION`

## 四、数据真实性保障（用户核心要求）

1. **行情数字** = 妙想 API 返回原样，脚本组装时标注数据日期
2. **持仓数字** = portfolio_data.json（用户确认数据），标注 `update_date`
3. **AI 硬性约束**：prompt 明确「禁止编造简报之外的任何数字」，简报没有的写「以 portfolio 数据为准」
4. **失败跳过**：行情/数据拉取失败 → 当天不发，绝不用猜测数据顶替
5. **两类数据日期分开标注**：实时行情 vs 持仓数据日期（如「周日休市，以上基于 8/7 数据」）

## 五、踩坑记录（2026-08-09）

| # | 问题 | 根因 | 解决 |
|---|------|------|------|
| 1 | cron 任务报 `Invalid session` | MessageType.value 是驼峰 `FriendMessage`，不是全大写 | session 写 `...:FriendMessage:...` |
| 2 | 板块数据解析错乱 | 板块类接口 entityName=指标名、table key=板块名（反的） | 检测到板块/指数/ETF 名时交换 entity/name |
| 3 | ETF 查询混入噪音 | 返回区间统计/业绩基准等行 | 过滤「至/区间/基准/收益率/合约」 |
| 4 | 脚本报密码环境变量缺失 | setx 写入注册表但**当前已开终端不继承** | 从注册表注入：`[Environment]::GetEnvironmentVariable(...,'User')`；计划任务不受影响 |
| 5 | 分类器拒绝硬编码密码 | 脚本明文写 AstrBot 密码 | 改读环境变量 `ASTRBOT_PASSWORD`（setx 用户级永久配置） |
| 6 | 创新药时间止损信号丢失 | pending_actions 的 name 不含「时间止损」（在 action 字段） | 匹配 name+action，并加「8/20」关键词 |
| 7 | 场外基金无盘中估值 | 妙想 API 查不到联接基金估值 | 持仓用 JSON 数据（标注日期），不硬查 |

## 六、故障排查指南（没收到推送时按顺序查）

| 步骤 | 查什么 | 判断方法 |
|------|--------|----------|
| 1 | 脚本是否运行 | 看 `daily_advice.log` 最后几行；或手动跑 `python daily_advice.py`（需 ASTRBOT_PASSWORD） |
| 2 | 计划任务是否触发 | `schtasks /Query /TN "Anchor每日建议"` 看下次运行时间；电脑是否开机、AstrBot 是否运行 |
| 3 | 行情是否拉取成功 | 日志出现「行情拉取失败」= 妙想 API 问题（code=113 次数超限 / code=114 key 失效 / 网络） |
| 4 | cron 任务是否创建 | 日志「cron 任务已创建: <id>」；没有 = AstrBot 登录/API 问题 |
| 5 | Agent 是否执行推送 | `docker logs astrbot --since 30m \| grep -E "cron\|send_message"`；看「Message sent to session weixin...」 |
| 6 | 微信是否在线 | 微信管道 token 可能过期（weixin_oc），需在 AstrBot 面板重新扫码/刷新 |
| 7 | 数据是否过期 | 简报会标注日期；如持仓日期过旧，需更新 portfolio_data.json（走「更新今日数据」流程） |

**最快定位方式**：对 Claude 说「看下 daily_advice 日志」，Claude 读 `daily_advice.log` + 容器日志即可定位到具体环节。
