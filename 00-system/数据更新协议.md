# Anchor 数据更新协议 v1.0

> 定义每层数据的更新频率、责任人、操作步骤。严格遵守，保证数据实时性和一致性。
> 生效：2026年8月6日

## 一、实时层（交易时段，秒~分钟级）

### 触发时机
- 交易时段（9:30-15:00）需要决策时
- 检查 DDX / 溢价率 / 板块资金流时
- 盘中突发事件需要数据支撑时

### 数据源
- **首选**：`mx-data` skill（东方财富官方API）
- **备选**：WebSearch（兜底）

### 操作步骤
```
1. 调用 mx-data skill 获取实时行情
2. 结果仅在当前对话中使用，不写入文件
3. 如果触发操作条件（止损/补仓等），标记到会话检查点
```

### 不更新文件
- ❌ 不更新 portfolio_data.json（那是收盘数据）
- ❌ 不运行 rebuild.py
- ✅ 只在对话中讨论，不做数据持久化

## 二、每日层（收盘后 ~15:30，一次/交易日）

### 触发时机
- 每个交易日收盘后（约15:30）
- 或晚上复盘时手动触发

### 更新内容
| 字段 | 来源 | 更新方式 |
|------|------|------|
| 市场行情（上证/科创50收盘价、涨跌幅） | mx-data | 手动填入 |
| 各持仓净值变化 | 天天基金/基金App | 手动填入 |
| 日盈亏 | 自动计算 | rebuild.py |
| 市场备注 | Claude 分析 | 手动填入 |
| DDX状态 | mx-data | 手动填入 |
| 纳指溢价率 | mx-data | 手动填入 |

### 操作步骤
```
1. 打开 portfolio_data.json（桌面）
2. 更新 market 区块（date, sh.close/change, kc.close/change, note）
3. 逐只更新 holdings_summary 中每只基金的 mv, pnl, day_pnl
4. 更新 total_assets, fund_account 等顶层汇总
5. 更新 watchlist 中每个品种的 today 字段
6. 更新 pending_actions 状态
7. 追加新的 daily_summaries 条目
8. 追加新的 chart_data 条目
9. 保存 JSON
10. 运行: python "Anchor/05-scripts/rebuild.py"
11. 确认: 桌面 portfolio_analysis.html 刷新成功
```

### 快捷命令（对Claude说）
```
"更新今日数据" → Claude 用 mx-data 获取收盘数据 → 更新 JSON → rebuild
```

## 三、每周层（周末，一次/周）

### 触发时机
- 周五收盘后或周末

### 更新内容
| 事项 | 操作 |
|------|------|
| 周报 | 生成 `04-reviews/weekly_report_YYYYMM_WX.md` |
| 仓位点检 | 检查四层占比偏离>5%？ |
| 规则检查 | 逐条扫描止损/止盈/时间止损触发 |
| 待办更新 | 更新 pending_actions |
| 记忆同步 | 更新 Claude memory 中的框架文件和持仓基准 |
| 体系总览 | 如有变更，更新 `ANCHOR_体系总览.md` |

### 操作步骤
```
1. 运行周报生成流程
2. 检查四层占比，记录偏离
3. 逐只过「持仓全面检查清单」
4. 同步 07-memory/ 到 Claude memory
5. 更新会话检查点
```

### 快捷命令
```
"生成周报" → Claude 生成完整周报
"仓位点检" → Claude 逐层检查占比
```

## 四、每月层（次月第1周，一次/月）

### 触发时机
- 次月第1-7天

### 更新内容
| 事项 | 操作 |
|------|------|
| 月度归因 | 盈亏拆解（beta/alpha）+ 胜率统计 + 违规记录 |
| 规则评审 | 逐条评估是否需要修改（三问评估） |
| 版本升级 | 如有规则变更，更新版本号+CHANGELOG |
| 框架文档 | 更新规则手册（01-rules/） |
| 历史归档 | 上月每日复盘归档，清理旧快照 |
| 记忆全面刷新 | 所有 memory 文件重新核对 |

### 操作步骤
```
1. 统计上月全部交易（笔数、胜率、盈亏）
2. beta/alpha 拆解（区分市场和选基）
3. 逐条检查规则是否需要修订
4. 三问评估任何新规则提案
5. 更新投资规则手册版本号
6. 更新 ANCHOR_体系总览.md
7. 同步所有 07-memory/
8. 更新 CLAUDE.md 中的版本信息
```

## 五、数据权威源

```
                    portfolio_data.json（桌面·唯一主数据源）
                         │
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼
    rebuild.py     sync_all.py    手动查看
          │              │
          ▼              ▼
   HTML看板(×2)   每日快照+Excel
   Snapshot(×2)   JSON副本(06-dashboard)
```

### 铁律
1. **portfolio_data.json（桌面）是唯一可编辑的数据源**
2. `06-dashboard/portfolio_data.json` 是只读副本，由 rebuild.py 自动同步
3. 所有生成文件（HTML/Snapshot/Excel）不手动编辑
4. 数据不一致时，以桌面 JSON 为准

## 六、数据新鲜度标记

每天更新后在 JSON 中记录：

```json
{
  "_meta": {
    "last_rebuilt": "2026-08-06",
    "data_freshness": {
      "market": "2026-08-06 15:30",
      "holdings": "2026-08-06 22:00",
      "watchlist": "2026-08-06",
      "rules_checked": "2026-08-06"
    }
  }
}
```

Claude 在每次对话开始时读取这个标记，判断哪些数据需要刷新。

## 七、会话连续性

### 跨对话状态传递

每次对话结束时，Claude 自动更新：
- `CLAUDE.md` — 最新状态摘要（数据日期、待办、下次检查日期）
- `00-system/会话检查点.md` — 详细的上次对话做了什么、接下来要做什么

新对话开始时，Claude 读取这两个文件就能立即恢复上下文。

### 记忆文件索引

`MEMORY.md` 维护所有记忆文件的索引。每次新增/修改记忆，自动更新索引。
