# FDIS项目可行性报告

> 评估对象：基金纪律化投资体系（FDIS）开源项目
> 评估人：基于109笔实盘交易+35天协作经验

---

## 一、一句话结论

> **值得做，但不要为了Star数做。** 这个项目的真正价值不在GitHub热度——在于把你的交易体系变成"可交付的产品"，通过社区反馈反向优化你的规则。Star数只是副产品。

---

## 二、诚实的三条判断

### 2.1 不会火——接受这个前提

| 原因 | 说明 |
|------|------|
| 纯文档仓库 | GitHub 99%的流量给代码项目，纯文档天生没流量 |
| 受众错位 | 真正需要这套体系的散户在雪球/小红书，不在GitHub |
| 没有技术壁垒 | 方法论项目容易被复制，差异化靠个人背书 |

> 预期Star：**200-500**（正常运营）到 **1000-2000**（理想情况）。不会过万，但做到细分第一没问题。

### 2.2 但值得做——价值不在Star

| 真正的价值 | 说明 |
|------|------|
| **固化你的体系** | 把你35天迭代了4版的规则变成结构化文档——你自己就是最大受益者 |
| **反向优化** | 社区反馈会发现你自己看不到的盲区（就像昨晚的审查报告发现了beta/alpha混淆） |
| **个人品牌** | "109笔实盘迭代出的纪律体系"——这个标签在投资圈比"10万粉博主"更有信任感 |
| **协作入口** | 以后再有人质疑你的规则——发个GitHub链接就行 |

### 2.3 做的话——必须加"轻工具"

纯文档上传=没人看。但只需要加一个工具：

```
仓位计算器（HTML/Excel）
  输入：总资产、风险偏好
  输出：四层配比、每只基金目标金额、止损价位

  这是你项目里唯一需要"代码"的部分
  其他都是文档——但这个小工具是流量入口
```

## 四、精简建议：不要一开始就做全套

### 4.1 你的方案太完整了——这是个问题

8个模块、30+个文件——对第一个版本来说太重了。GitHub上成功的开源项目，第一个版本都很小。

### 4.2 MVP应该只有这3个文件

```
fund-discipline-invest-system/
├── README.md              # 你是谁、这项目干嘛、3分钟上手
├── 规则手册_v3.2.md       # 你已经写好了（桌面上的那个）
└── 仓位计算器.html         # 单个HTML文件，浏览器打开就能用
```

> **这三个文件上传，就够了。** 剩下的模块在有人关注后再补。一开始就做全套=完美主义陷阱=大概率烂尾。

## 五、推广路径：不靠GitHub靠外部

| 阶段 | 平台 | 内容 | 时间 |
|------|------|------|------|
| 冷启动 | 雪球/知乎 | 发一篇《我做了109笔基金交易，总结了这套纪律体系》 | 上传当天 |
| 冷启动 | V2EX/掘金 | 技术视角：《用Git管理投资纪律——我的开源实验》 | 上传当天 |
| 稳定期 | GitHub | 回应用户Issue，每月更新一次CHANGELOG | 长期 |
| 增长期 | 小红书 | 截图你的持仓分析+框架图，引流 | 有内容积累后 |

> 关键：**每篇推广文只讲一个痛点**。不要一口气介绍全套——没人看得完。
