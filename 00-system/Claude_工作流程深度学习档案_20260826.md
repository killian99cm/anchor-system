### 6.1 工具调用序列 TOP5（8/26 主会话 3544 次调用）
| 模式 | 次数 | 含义 |
|:--:|:--:|---|
| Bash→Bash | 1086 | 脚本链式执行（check→sync→rebuild→git） |
| Edit→Edit | 544 | 连续改码后统一验证 |

| Edit→Bash | 169 | 改完立即跑脚本验证 |
| Read→Edit | 134 | 先读模板/检查点再改 |

**贯穿规律**：TodoWrite 开任务清单，全程可见；「先读后改 → 改完验证 → git 提交」三段式纪律。

### 6.2 报告生成标准流程（周报实证）
`TodoWrite → Glob 定位脚本 → Read（脚本+模板+检查点三件套）→ Bash 跑 → 交叉校验数据 → date 确认时间 → Write 落盘 → Edit 检查点 → 收尾`

### 6.3 决策日志触发时机
- 决策确定后**同一轮对话内立即记录**（不做事后补账）→ 保证 T+3 复盘数据完整
- `--add 类型 标的 判定 金额 理由` / `--backfill` 补录 / `--review 对错 盈亏点 说明` / `--due` 到期提醒

### 6.4 建设期 vs 现行风格
- **建设期（8/7）**：探索式、路径不固定、边做边沉淀规则进记忆
- **现行（8/25-26）**：体系化、脚本运行为主（Bash 占 44%）、重测试、git 版本化、决策闭环自动化

## 八、对 WorkBuddy 协作的 4 条改进建议

1. **复制三段式纪律**：任何操作 = 先读（检查点/模板/数据）→ 改 → 立即验证 → 登记检查点——与 Claude 对齐节奏
2. **决策即记录**：WorkBuddy 自动化产出操作建议时，同轮把建议写入 decision_log（--add），避免"自动化建议无人记决策"
3. **编码环境前置**：统一 Python 绝对路径 + utf-8 编码（GBK 坑已在 gen_intraday_signal/stop_profit_backtest 修复）——新脚本默认带 reconfigure
4. **版本单一来源**：体系版本以 CLAUDE.md 为准（v4.3.1），WorkBuddy 记忆/看板同步跟进，避免双轨版本混乱
