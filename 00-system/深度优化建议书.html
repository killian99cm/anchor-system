1摘要与目标

本建议书的三大目标

目标一 · 补上自动化空白

原体系依赖 Windows 计划任务（14:30 推送 / 21:30 同步 / 21:40 兜底 / 实时监听），但复盘执行、周报、月度归因等环节缺少定时驱动。本次在 WorkBuddy 配置 4 个定时自动化补齐。

目标二 · 扭转盈利端短板

8/21 六透镜归因铁证：方向准确率 80% 但加仓准确率 40%、盈亏比 0.93:1。P1 清单聚焦买点评分卡落地、盈亏比闸门、止盈重构回测。

核心命题：「方向对（80%）→ 买卖点差 + 亏损拖延 + 收割太早 → 收益没兑现」。一切优化围绕把判断力转化为收益，8/31 月度归因是首个判定日。

9风险与降级

场景降级行为
数据未更新（周末/节假日/忘记更新）21:00 复盘 → 「仅提醒」文件；14:30 信号 → 提示核对数据；周报/归因 → 骨架 + 待填
sync_all 失败（含 rebuild 中止）停止后续步骤，错误摘要写入复盘文件，不跑 smoke
smoke 失败记录「N 项异常」不中断，报告里标红
规则引擎不可用（14:30）仅提醒文件 + 提示核对数据，绝不编造数字
月度归因真实盈亏缺失只生成骨架 + 醒目铁律提醒，不代填总账
API 与数据库自动化不同步数据库另有 2 条旧 ACTIVE 记录（16:00 复盘 / 9:00 Viking）当前 API 作用域不可见；不删除、不冲突，职责已划分
